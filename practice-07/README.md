## Устройство решения

App хранит tasks, filters, editingId и следующий id через useState. TaskForm хранит draft и errors; остальные компоненты получают props и сообщают действия через callbacks. TaskList выводит заглушку «Список задач пуст» или map с key=task.id. TaskFilters подсвечивает активную кнопку через aria-pressed. Видимая выборка и статистика вычисляются при рендере, не дублируются в state.

В task-service.js используются map, filter и spread. Изменённая запись копируется, исходные аргументы не меняются. При редактировании сохраняются id и completed. Ключ формы editingId или new сбрасывает чужой черновик; confirm вызывается до функционального обновления. Проверяются title после trim, приоритет и существующая категория. id берётся из отдельного счётчика, а не из длины выборки.

## Ответы на контрольные вопросы

1. **Чем JSX отличается от HTML-строки?.** JSX преобразуется сборщиком в описание React-элементов. Выражения в фигурных скобках вычисляются, пользовательский текст экранируется.
2. **Props и состояние.** Props передаёт родитель; useState хранит изменяемые данные компонента. Дочерний компонент не изменяет props.
3. **Почему не обычная переменная?.** Её присваивание не запрашивает новый рендер и не сохраняет значение между вызовами компонента.
4. **Функциональное обновление.** Когда новое значение зависит от предыдущего: setTasks(previous => toggleTask(previous, id)).
5. **Почему нельзя менять объект внутри копии массива?.** Копия массива сохраняет ссылки на объекты. Для изменённой задачи нужен новый объект через spread.
6. **Зачем key?.** Стабильный task.id сохраняет соответствие элемента и его состояния при удалении. Индексы смещаются.
7. **Зачем вычислять выборку и статистику?.** Они полностью определены tasks и filters. Отдельный state создаёт лишнюю синхронизацию.
8. **Как ребёнок сообщает действие?.** Вызывает переданную функцию onToggle, onEdit или onDelete с id.
9. **Управляемое поле.** value берётся из state, onChange обновляет state. Начальные значения строковые.
10. **Почему преобразуется categoryId?.** HTML select возвращает строку, а модель хранит число. Валидатор проверяет допустимость категории.
11. **Что делает смена key формы?.** Размонтирует прежнюю форму и создаёт новую с правильным начальным черновиком.
12. **Почему confirm вне updater?.** Updater должен быть чистым: React в StrictMode может вызывать его повторно.
13. **Пустой набор и пустая выборка.** tasks.length показывает весь набор, visibleTasks.length — результат условий. Нулевой результат не является ошибкой.
14. **Что проверяет npm test?.** Чистые предметные функции и отсутствие мутаций. Внешний вид, клавиатуру и события формы проверяет отдельный браузерный прогон.
15. **Что изменится в ПР8?.** Источник данных станет сервером, операции — асинхронными. Загрузкой и ошибками будет управлять useTaskData.

## Вывод

React управляет интерфейсом через состояние и неизменяемые обновления. При переходе к ПР8 локальный массив заменяется серверным снимком и асинхронными операциями; компоненты сохраняют свои роли.
