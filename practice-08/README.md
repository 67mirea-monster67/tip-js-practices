## Запуск

Из `practice-08` выполните `npm ci`. Первый терминал: `npm run api`; второй: `npm run dev`. API http://127.0.0.1:5505/api, Vite по умолчанию http://127.0.0.1:5173/. Одновременно с ПР7 можно запустить `npm run dev -- --port 5174`.

Проверки: `npm test`. Сборка: `npm run build`, просмотр: `npm run preview`. Сервер должен продолжать работать. Перед запуском ПР9 на 5505 остановите API ПР8 через Ctrl+C. Для другого API используйте VITE_API_URL в `.env` по образцу, затем перезапустите Vite. `.env` не публикуется.

## Результат и архитектура

App хранит фильтры и снимок редактируемой записи. useTaskData хранит snapshot, status, error, mutationError, pending и revision. TaskForm управляет черновиком и ждёт Promise<boolean>. task-api.js описывает предметные операции; api-client.js формирует HTTP, тайм-аут и ошибки. Учебный сервер хранит данные до остановки; обновление страницы их не удаляет.

Эффект зависит от api, четырёх значений фильтров и revision. Он загружает задачи и категории параллельно, не фильтрует серверную выборку повторно. Cleanup выставляет active=false и вызывает abort. Проверка актуальности стоит в try и catch. Ошибка чтения сохраняет последний успешный снимок. Ссылка api стабильна: создана вне React.

Служебные mounted и currentMutation — ref. Немедленная установка контроллера блокирует две синхронные мутации. Контроллер чтения и записи различаются. Успешная запись возвращает true и увеличивает revision; новый эффект использует текущие фильтры. Ошибка последующего GET не меняет подтверждённый успех POST. finally освобождает только собственную блокировку. После unmount старый callback не отправляет новую запись.

Для КР3 добавлены tasks и isLoading как производные aliases. Откройте `http://127.0.0.1:5174/?trace` и Console: выводятся фактические isLoading и tasks.length. В обычном запуске диагностические логи выключены. StrictMode может показать true 0 дважды; затем false 7 для варианта 1.

## Ответы на контрольные вопросы

1. **Зачем эффект?.** Запрос — побочное действие после рендера. Запрос в теле компонента повторялся бы на каждом рендере.
2. **Когда вызывается cleanup?.** Перед следующим setup при изменении зависимостей и при размонтировании; StrictMode дополнительно проверяет setup/cleanup в разработке.
3. **Почему callback эффекта не async?.** React ожидает функцию cleanup или undefined, а async-функция возвращает Promise. Внутри эффекта вызывается отдельная async load.
4. **Зависимости эффекта.** api, q, completed, priority, categoryId, revision. snapshot — результат, его включение вызвало бы повторную загрузку после каждого успеха.
5. **Зачем стабильный api?.** Новая ссылка считалась бы новой зависимостью и запускала бы эффект снова. Клиент создаётся один раз в config.js.
6. **Зачем active вместе с AbortController?.** Отмена не гарантирует, что транспорт или заглушка не вернёт старый результат. active запрещает применять его к состоянию.
7. **Почему проверка нужна в catch?.** Поздняя ошибка старого запроса иначе затёрла бы успешное состояние нового.
8. **Что проверяет StrictMode?.** Корректность очистки и повторного setup; повторные true 0 в Console допустимы и не означают два POST.
9. **Почему pending недостаточно?.** State обновится после рендера. Два синхронных вызова могут увидеть false; ref блокирует второй вызов немедленно.
10. **Что означает true при последующей ошибке GET?.** Сервер подтвердил запись. Ошибка обновления хранится в error, а не mutationError, и не отменяет сохранение.
11. **Почему нельзя повторять POST автоматически?.** Сервер мог создать запись до потери ответа. Повтор способен создать дубликат; сначала нужно обновить список.
12. **Почему фильтр не отменяет запись?.** Фильтр относится к чтению. Мутация использует другой контроллер, а новый GET берёт актуальные фильтры.
13. **Отмена — откат?.** Нет. Она отменяет ожидание клиента, но уже выполненное сервером изменение остаётся.
14. **Что такое meta.total?.** Количество задач в полученной серверной выборке, а не во всём хранилище.
15. **Что требует настоящего браузера?.** CORS, реальная форма, диалоги удаления, Network, клавиатура и собранный preview.
