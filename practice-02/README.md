## 2. Модель данных

Задача содержит четыре поля: `id`, `title`, `completed`, `priority`.

`id` — положительное безопасное целое число.  
`title` — строка от 1 до 100 символов после `trim()`.  
`completed` — boolean.  
`priority` — `low`, `medium` или `high`, по умолчанию `medium`.

`id` не равен индексу, потому что индекс зависит от положения записи в массиве и меняется после удаления. Идентификатор используется для поиска конкретной задачи.

`getTaskStats` возвращает процент числом, потому что это результат вычисления. Округление выполняется только при выводе через `toFixed(1)`.

При изменении задачи создаётся новый массив и новый объект только для изменяемой записи. Остальные объекты используются без изменения.

## 3. Общий сценарий

| Этап | Ожидание | Фактический результат | Итог |
|---|---|---|---|
| Исходный набор | 4 / 2 / 2 / 50.0% | 4 / 2 / 2 / 50.0% | Пройдено |
| Добавление id 20 | 5 / 2 / 3 / 40.0% | 5 / 2 / 3 / 40.0% | Пройдено |
| Выполнение id 4 | 5 / 3 / 2 / 60.0% | 5 / 3 / 2 / 60.0% | Пройдено |
| Переименование id 10 | 5 / 3 / 2 / 60.0% | 5 / 3 / 2 / 60.0% | Пройдено |
| Удаление id 7 | 4 / 3 / 1 / 75.0% | 4 / 3 / 1 / 75.0% | Пройдено |

Итоговые идентификаторы: `[1, 4, 10, 20]`.

При повторном добавлении `id = 20` возвращается ошибка о существующем идентификаторе. Текущее состояние при этом не заменяется.

`demoTasks` после всех операций остаётся в исходном состоянии.

## 6. Расширение

Реализовано расширение поиска задач по части названия в `src/task-extra.js`.

Поиск не зависит от регистра, учитывает `trim()` и возвращает новый массив. Например, запрос `ПРОВЕР` находит задачу с названием «Проверить...».
