## Задание 2. Исследование типов и преобразований

| № | Выражение | Ожидание до запуска | Фактическое значение | Тип результата | Объяснение |
|---:|---|---|---|---|---|
| 1 | `"8" + 2` | `"82"` | `"82"` | `string` | Оператор `+` при наличии строки выполняет конкатенацию. |
| 2 | `"8" - 2` | `6` | `6` | `number` | Перед вычитанием строка преобразуется в число. |
| 3 | `Number("8") + 2` | `10` | `10` | `number` | `Number("8")` явно преобразует строку в число. |
| 4 | `"12" > "3"` | `false` | `false` | `boolean` | Обе стороны являются строками, поэтому сравнение идёт лексикографически. |
| 5 | `12 === "12"` | `false` | `false` | `boolean` | Строгое равенство не преобразует разные типы. |
| 6 | `Number("")` | `0` | `0` | `number` | Пустая строка при числовом преобразовании становится нулём. |
| 7 | `Number("text")` | `NaN` | `NaN` | `number` | Строка не может быть преобразована в корректное число; результат — `NaN`. |
| 8 | `Boolean("false")` | `true` | `true` | `boolean` | Любая непустая строка является истинным значением. |
| 9 | `typeof null` | `"object"` | `"object"` | `string` | Это специальное историческое поведение `typeof`; результат оператора сам является строкой. |
| 10 | `typeof NaN` | `"number"` | `"number"` | `string` | `NaN` относится к числовому типу, а `typeof ...` возвращает строку. |

| Всё выполнено | `5, 5, 2` | 0 дней; цикл не запускается | 0 дней; цикл не запускается | Пройдено |
| Пустой набор | `0, 0, 2` | 0 дней; цикл не запускается | 0 дней; цикл не запускается | Пройдено |

| Некорректное completed | `5, 6, 2` | Ошибка | Ошибка | Пройдено |

Для планирования используется `while`. На каждой итерации уменьшается оставшееся количество задач; последняя итерация ограничивается через `Math.min()`, поэтому остаток не становится отрицательным.

## Задание 5. Поиск логических ошибок через DevTools

### Исходная версия

В исходном варианте были две логические ошибки:

| Ошибка | Что наблюдалось | Причина | Исправление | Результат после исправления |
|---|---|---|---|---|
| Обработка количества задач | Получалось `32` вместо `5` | Две строки складывались оператором `+` как текст | Явно преобразовать обе строки через `Number()` | `Выполнено: 5`, `Осталось: 3` |
| Граница цикла | Контрольная сумма была `6` | Условие `taskNumber < 4` не включало число 4 | Заменить на `taskNumber <= 4` | `Контрольная сумма: 10` |

### Исправленный результат

```text
Выполнено: 5
Осталось: 3
Контрольная сумма: 10
```

Точка останова устанавливалась на вычислении `completedTotal`, после чего через Step over проверялось изменение его значения и типа. В цикле отдельно проверялась граница `taskNumber <= 4` и накопление `controlSum`.

Иллюстрация точки останова должна быть добавлена после фактической остановки программы в Chrome DevTools. Файл для неё: `screenshots/debug-breakpoint.png`. Скриншот должен показывать строку остановки и исследуемые значения.

## Дополнительное задание. Вариант А — строковый ввод

Дополнительно реализован файл `js/progress-input.js`. Он принимает количества задач как строки, удаляет пробелы по краям, отклоняет пустой ввод, выполняет явное преобразование через `Number()` и затем проверяет тип результата, диапазоны и целочисленность.

### Проверки расширения

| Входные данные | Ожидаемый результат | Фактический результат | Итог |
|---|---|---|---|
| `" 12 "`, `"5"` | 7 осталось; 41.7%; «В работе» | 7 осталось; 41.7%; «В работе» | Пройдено |
| `""`, `"5"` | Ошибка пустого ввода | Ошибка пустого ввода | Пройдено |
| `"   "`, `"2"` | Ошибка пустого ввода | Ошибка пустого ввода | Пройдено |
| `"abc"`, `"2"` | Ошибка некорректного числа | Ошибка некорректного числа | Пройдено |
| `"2.5"`, `"1"` | Ошибка дробного значения | Ошибка дробного значения | Пройдено |
| `"Infinity"`, `"1"` | Ошибка недопустимого числового значения | Ошибка недопустимого числового значения | Пройдено |
| `null`, `"1"` | Ошибка: значения должны быть строками | Ошибка: значения должны быть строками | Пройдено |
| `"5"`, `undefined` | Ошибка: значения должны быть строками | Ошибка: значения должны быть строками | Пройдено |

Просто вызвать `Number()` недостаточно: например, `Number("")` даёт `0`, а `Number("   ")` также даёт `0`, поэтому пустой ввод нужно отсеять до преобразования. Кроме того, отрицательные, дробные и бесконечные значения требуют отдельных проверок.
