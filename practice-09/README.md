## Запуск и режимы

Из `practice-09`:

```sh
npm ci
npm start
npm test
```

Обычная ПР9 на http://127.0.0.1:5505/api: GET /health, /categories, /tasks, /tasks/:id; HEAD и OPTIONS. POST/PATCH/DELETE возвращают 405 с Allow. Другой порт: `npm start -- 5515`. `.env` загружается только явной командой `node --env-file=.env src/server.js`.

КР3 требует POST-валидацию и JSON-массив списка, которых нет в контракте чтения ПР9. Для этого служит отдельный явный режим:

```sh
npm run kr3
```

Он запускается вместо обычного сервера, на том же 5505: GET /tasks возвращает массив, POST /tasks создаёт валидную задачу (201, Location) или возвращает 400 INVALID_TASK. Требуются title, priority, числовой categoryId. title нормализуется через trim, длина 1–100; categoryId должен существовать. Неизвестные поля запрещены, completed назначает сервер. Невалидный JSON → 400, Content-Type → 415, тело больше 16 KB → 413. Полный CRUD ПР10 в это дополнение не входит.

Не направляйте клиент ПР8 на режим КР3: ему нужна оболочка data/meta и полный CRUD учебного API ПР8. На обычную ПР9 его можно направить для чтения; изменения вернут 405.

## Модули

validation.js разбирает и проверяет id/query/draft. task-service.js выбирает и ищет задачи без HTTP. store.js владеет копиями данных конкретного приложения и счётчиком id. routes.js связывает запросы с сервисами и ответом. app.js регистрирует общие заголовки, OPTIONS, Router, 404 и errorHandler. server.js проверяет порт и вызывает listen. Импорт createApp не открывает порт.

Параметры списка проверяются через URLSearchParams до преобразования: неизвестные имена и повторы дают 400. Строки true и false преобразуются явно; null означает отсутствие ограничения. id требует полного совпадения /^[1-9]\d*$/ и Number.isSafeInteger. Поиск регистронезависим, четыре условия объединены И. Объекты, возвращаемые store, копируются.

## Контракт обычной ПР9

`GET /api/tasks?completed=false&priority=high&categoryId=2` → 200, `{data:[задачи 4 и 34],meta:{total:2,filters:{completed:false,priority:"high",categoryId:2,q:""}}}`.

`completed=0` → 400 INVALID_QUERY. `/tasks/4abc` → 400 INVALID_ID. `/tasks/2` → 404 TASK_NOT_FOUND, details.id=2. Неизвестный путь → 404 ROUTE_NOT_FOUND. POST /tasks → 405 METHOD_NOT_ALLOWED, Allow: GET, HEAD, OPTIONS. Неожиданное исключение → 500 INTERNAL_ERROR без стека.

JSON-ответы содержат application/json, Cache-Control: no-store и CORS. HEAD не содержит тела. OPTIONS возвращает 204. meta.total — длина выборки.

## Ответы на контрольные вопросы

1. **Node.js и браузер.** Node.js работает вне браузера, имеет модули http и файловые API, но не DOM и window.
2. **Что выбирает маршрут?.** Метод и путь. Query не входит в путь, обработчик списка читает его отдельно.
3. **params и query.** req.params.id берётся из /tasks/:id; URLSearchParams содержит completed, priority, categoryId и q после знака вопроса.
4. **Почему false преобразуется явно?.** Boolean('false') равно true. После проверки строки используется raw === 'true'.
5. **Зачем проверять весь id?.** parseInt принял бы 4abc. Регулярное выражение и Number.isSafeInteger отклоняют неверный формат и небезопасные числа.
6. **Пустой список 200 и задача 404.** Поиск без совпадений успешно вернул пустой массив; отсутствующего отдельного ресурса нет.
7. **TASK_NOT_FOUND и ROUTE_NOT_FOUND.** Первое означает корректный маршрут с отсутствующим id, второе — неизвестный путь.
8. **405 и Allow.** Путь известен, но метод не поддержан. Allow перечисляет допустимые методы конкретного ресурса.
9. **meta.total.** Длина массива после всех фильтров; не исходные 12.
10. **Порядок middleware.** Общие заголовки и OPTIONS, маршруты, 405 известных путей, 404, затем errorHandler.
11. **Четыре параметра errorHandler.** По сигнатуре (error, req, res, next) Express распознаёт обработчик ошибок.
12. **Почему createApp отделён от listen?.** Импорт не открывает порт. Тесты получают независимое приложение и запускают его на свободном порту.
13. **Ответ при 500.** Общий код INTERNAL_ERROR и понятное сообщение. Стек и внутренний текст исключения клиенту не отправляются.
14. **CORS и авторизация.** CORS ограничивает чтение ответа JavaScript-кодом браузера. Он не проверяет права и не запрещает curl.
15. **Что потребуется в ПР10?.** Добавить полный PATCH/DELETE и валидацию изменений, согласовать весь CRUD-контракт с клиентом ПР8. В дополнении КР3 реализован только POST.
