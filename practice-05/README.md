## Цикл событий

Прогноз: A B C D E F. Фактически: A B C D E F, см. [вывод](protocols/event-loop.txt). A/B/C выполняются синхронно. then(D) и продолжение await(E) — микрозадачи, зарегистрированные в таком порядке. F — следующая задача таймера, поэтому 0 мс не означает немедленный вызов. При удалении обработчика D вывод будет A B C E F, порядок остальных сообщений сохранится.

## HTTP и архитектура

buildUrl нормализует базовый HTTP(S) URL без query/hash и кодирует значения URLSearchParams. Пропускаются только null/undefined/пустая строка; false сохраняется. requestJson отправляет GET с Accept:application/json и AbortSignal. Сначала проверяет response.ok; HTTP-ошибка сохраняет status/code/details даже при не-JSON теле. 204 возвращает null; успешный непустой ответ проверяется по Content-Type и разбирается JSON. finally очищает таймер и подписку на внешний сигнал.

ApiError хранит kind, status, code, details, url и cause. Ошибка, уже являющаяся ApiError, повторно не превращается в network. fetchFn передаётся зависимостью для проверок без сети.

task-api.js допускает фильтры completed/priority/categoryId/q, проверяет типы и нормализует q. Проверяются поля задачи, категории, уникальность id и соответствие meta.total длине массива. loadInitialData запускает задачи и категории совместно через Promise.all. variant.js содержит только номер 1 и {completed:false}; main.js выводит результат и отдельно перехватывает 404.

## Ответы на контрольные вопросы

1. **Чем Promise отличается от уже полученного значения?**<br>
   Promise представляет будущий результат, его ещё нужно дождаться.

2. **Какие три состояния имеет Promise?**<br>
   pending, fulfilled, rejected.

3. **Почему код после вызова `fetch` может выполниться до обработки ответа?**<br>
   fetch начинает асинхронную операцию; синхронный код текущего стека выполняется дальше.

4. **Чем микрозадача отличается от задачи таймера в эксперименте этой работы?**<br>
   Микрозадачи Promise выполняются после стека перед следующей задачей таймера.

5. **Что возвращает `async`-функция?**<br>
   Promise, который исполняется возвращённым значением или отклоняется исключением.

6. **Как ошибка ожидаемого Promise попадает в `catch`?**<br>
   await отклонённого Promise выбрасывает причину в текущем async-контексте, её перехватывает try/catch.

7. **Почему `fetch` не отклоняется при обычном ответе `404`?**<br>
   HTTP 404 — полученный HTTP-ответ, а не отсутствие сетевого ответа.

8. **Что означает `Response.ok`?**<br>
   true для статусов 200–299.

9. **Почему `response.json()` необходимо ожидать?**<br>
   Чтение потока тела и разбор JSON также асинхронны и возвращают Promise.

10. **Зачем проверять `Content-Type`?**<br>
   Чтобы не трактовать HTML или обычный текст как JSON успешного ответа.

11. **Почему синтаксически корректный JSON может быть непригоден приложению?**<br>
   JSON может содержать данные неправильной схемы: строковый id, дубликаты или неверный completed.

12. **Для чего используется `URLSearchParams`?**<br>
   Для корректного кодирования query без ручного склеивания строк.

13. **Почему `false` нельзя отбрасывать как пустое значение фильтра?**<br>
   false означает невыполненные задачи, это содержательный фильтр.

14. **Чем HTTP-ошибка отличается от сетевой?**<br>
   При HTTP-ошибке есть Response и статус; при сетевой ответа нет.

15. **Чем тайм-аут отличается от явной отмены?**<br>
   Тайм-аут задаётся сроком ожидания; явная отмена вызывается внешним AbortController.

16. **Что делает `AbortController`?**<br>
   Передаёт отмену подписанным операциям через signal.

17. **Когда два запроса можно ожидать через `Promise.all`?**<br>
   Если запросы независимы: задачи не требуют результата категорий и наоборот.

18. **Что произойдёт при отказе одного Promise внутри `Promise.all`?**<br>
   Общий Promise отклоняется первой причиной отказа.

19. **Отменяет ли `Promise.all` остальные операции автоматически?**<br>
   Нет. Для прекращения запросов нужны AbortSignal и явная отмена.

20. **Зачем общий HTTP-клиент отделён от `task-api.js`?**<br>
   Общий клиент обрабатывает транспорт; предметный модуль знает маршруты и схему задач.

21. **Для чего `fetchFn` передаётся аргументом?**<br>
   Чтобы подменять fetch управляемой функцией в проверках без реальной сети.

22. **Что проверяют модульные тесты без сети?**<br>
   URL, параметры fetch, заголовки, обработку Response, ошибки, схему и порядок запросов.

23. **Что дополнительно подтверждают интеграционные тесты?**<br>
   Совместимость клиента с настоящим локальным сервером, CRUD и реальную отмену.

24. **Почему CORS проявляется в браузере, но не проверяется запросом Node.js?**<br>
   CORS — политика браузера. Node.js не применяет ограничения origin страницы.

25. **Какая часть решения будет повторно использована в ПР6?**<br>
   HTTP-клиент и предметные методы чтения; в ПР6 они расширены изменяющими методами.
